- ≤640px 基础响应式已上线，新功能不得破坏。

## 1. BirdTrace 是什么

四步推理：

1. 观鸟数据只有三个维度：**地点 × 时间 × 鸟种**。观鸟者的每个真实问题都是固定两维、问第三维。
2. 回答所需的数据已经存在：中国观鸟记录中心积累了大量维度齐全的公民科学记录。数据不是瓶颈。
3. 瓶颈是界面。现有形态是「报告的提交与检索」——用户要自己翻列表、数频率、判断样本，数据和决策之间隔着人肉计算。
4. 这层界面已被 eBird Explore 验证；中文观鸟数据还没有对应物。

**BirdTrace = 给中国观鸟数据补上这层界面**，把记录组织成三种问题的直接答案：

| 问题 | 固定 → 问 | 答案 |
|---|---|---|
| **看什么** | 地点+时间 → 鸟种 | 鸟种名录，按遇见率排序，样本量透明 |
| **何时去** | 地点+鸟种 → 时间 | 全年频率柱图 + 最佳时间窗口 |
| **去哪儿看** | 鸟种(+时间) → 地点 | 分布地图：在哪、哪个点最值得去 |

三问之上加一层**地区探索页**（实体页）：点任一地点看它的全貌（热点、鸟种、全年规律、近期动态），是三问的交汇。

它不生产数据、不替代记录中心——它让已有数据回答观鸟者的真实问题，让每条公民科学记录产生更多次价值。

**demo 定位**：当前是 demo，不是全量产品。真实数据是很小的切片（丽江、拉萨两城，2024–2025，集中 5–6 月）。切片内每个数字来自真实记录，证明界面用真数据能跑通；切片外用示例数据补齐并显式标注。所有展示场合明确说明局限。

**产品原则（贯穿所有功能）：**

- **数据诚实**：每个数字标来源、覆盖、样本量；样本薄的明确说薄；真实与示例数据绝不混淆（§5 硬约束）。
- **答案优先**：页面第一眼是结论（速读条、最佳窗口、最优鸟点），推导过程收在一层之下。
- **开放数据接口**：数据层与展示层解耦（§6.2），可平滑接入更多数据源。

### 🔒 合作提案方向（内部，提案会前不外发，会上口头呈现）

提议把这层界面做成**记录中心官方出品**，两种形态可并行可分步：①集成进现有网站的「探索」模块——用户交完记录，就地看到数据能回答什么；②官方独立小程序，面向移动端与出行场景。

角色分工：产品官方出品，数据与品牌归记录中心；BirdTrace 开发者以编外开发身份参与共建。数据侧共建（空白格激励 §9.1、鸟点主数据 §9.2）均为提案，与朱雀会确认后启动。

## 2. 用户故事

产品服务观鸟者，但提案要说服数据方——两组视角。

**数据方（记录中心 / 朱雀会），提案脊柱：**

- **DS-01 真实证明**：用你们自己的真实数据就能跑，不是演示假数据。
- **DS-02 诚实呈现**：样本量、覆盖、月度分母全摊开——诚实即数据机构的公信力。
- **DS-03 反哺采集**：空白格图层、鸟点共建，直接服务采集增长（§9）。
- **DS-04 零负担集成**：静态、无后端，可嵌入现有网站或做官方小程序（§6.1）。
- **DS-05 权责清晰**：数据与品牌归记录中心，CC 开放共享，开发方共建身份（§8）。

（DS-04/05 含合作策略，🔒 提案会前不外发，会上口头。）

**观鸟者（产品终端用户）：**

- **US-01 看什么**：定了地点和时间，从城市收敛到鸟点，看该点名录和各鸟遇见率。
- **US-02 分布图**：选一个鸟种看地图，圆点大小=记录数、颜色=季节，一眼看出在哪、哪季最集中。
- **US-03 地区探索页**：一页看全某地的热点地图、频率排行、季节直方图、近期记录。
- **US-04 多物种柱图**：柱图叠加多个目标鸟种，找时间窗口交集，定最优行程。
- **US-05 频率网格**：一张「鸟种×月份、格深=频率」网格扫出全年规律，不用逐个点。
- **US-06 目标鸟种**：「看什么」切到「该地区有、我还没见过」视角，按频率排缺失鸟种。
- **US-07 近期记录流**：倒序看最近报告——谁、何时、记了什么，判断活跃度与数据新鲜度。

### 🔒 内部用户故事（交付版删除）

- **US-09 数据源可切换**（工程）：数据层与展示层解耦，源可在示例数据 / 记录中心导出 / eBird API 间切换，接新源不改前端逻辑。

## 3. MVP 范围

**数据现状（决定每个功能的定位）：**

1. 空间：只有云南 + 西藏部分地区，demo 只开放丽江、拉萨两城。
2. 时间：2024–2025 两年，集中 5–6 月（行程驱动抓取；云南另有少量 1/2/3/12 月省级样本，西藏基本只有 6 月 + 一次「最近」扫）。
3. 推论：12 个月维度的可视化（频率网格、多物种柱图、季节直方图）在 5–6 月外基本空——**纯真实数据画不出「全年规律」**。

因此 **MVP 整体定位是 demo**：交互层全做真；数据层「真实切片 + 示例数据」并用——真实切片证明界面能跑通，全年/全国维度用示例数据补齐并显式标注（§5）。后续两条路都开着：按维度补拉数据，或等数据合作后整体替换。

**并用规则**（§5 推论）：同一图表内不真假混排；示例数据版整体切换、整体标注（provider isDemo）——与真实版一键切换，正是给数据方看的接口能力。

| 功能模块 | 数据 | 定位 |
|---|---|---|
| 「看什么」polish | 真实切片（丽江/拉萨） | 真实数据主打 |
| 鸟种分布图 | 示例数据（全国尺度，超出覆盖） | 示例数据 |
| 地区探索页 | 真实切片（regions/*.json 已有；季节直方图如实显示 5–6 月偏斜） | 真实数据主打 |
| 多物种柱图 | 真实 5–6 月 + 其余月稀疏；演示预设有跨月数据的云南鸟种，或切示例版并标注 | 真实+示例并用 |
| 频率网格 | 真实版如实显示稀疏（本身是诚实性展品），另备示例版演示「数据全了什么样」 | 真实+示例并用 |
| 目标鸟种 | 真实切片 + 本地标记（useMarks） | 真实数据主打 |
| 近期记录流 | 真实切片（时间范围如实标注） | 真实数据主打 |
| 招牌种 badge（加分项） | 真实（客户端计算） | 真实数据主打 |

### 🔒 本次不做什么（内部，交付版删除；落档防重复评估，不因工期宽裕而提前纳入）

- **账号系统实现**：产品必备（§8）但不在本轮；本轮用本地 useMarks + 导出/导入过渡。
- **完整移动端 IA**：≤640px 断点已上线且不得破坏即可；完整 IA 见 design_spec §2，留后续。
- **点位详情页（Hotspot 档案页）**：组件与地区探索页全复用、建页成本低，真正前置是鸟点主数据整理（§9.2）。
- **AI 自然语言摘要**（"夏候鸟已到齐…"）：Backlog。
- **居留型标签**（留鸟/夏候/冬候/旅鸟）：推断准确度不足，权威源未接入。
- **「何时去」旬级下钻**：月级够演示。
- **分布图接真实坐标**：坐标管线（GCJ-02 验证、高德 key）不在本轮。
- **eBird API 实际集成**：仅规划切换接口，不做实际调用。
- **实时同步 / 在线后端**：维持静态 JSON。
- **敏感物种坐标脱敏**：依赖与数据方的治理协议（§10），演示前不触碰。
- **频率网格市/县级下钻**：数据粒度只到 province bundle。
- **近期记录流明细补抓**：「明细待抓」诚实标注即可。
- **目标鸟种跨地区合并视图**：仅支持单次选定范围。
- **export_json.py 改动**（除近期记录流可选的 recent.json 外）。注：spot 级 `district` 字段已入 region_bundle，Amber 决定暂不重跑导出启用，不算本轮额度。
- **地区间横向对比、用户自定义区域、历史趋势（多年对比）**。
- **社区目标鸟**（eBird Community Targets）：「今年还没人报」需当年实时数据，静态快照语义不成立；支持增量更新后再评估。
- **周级（48 格）频率柱图**：导出是月粒度。Backlog（迁徙种过境窗口月级分辨不出，是真实需求）。
- **置信度徽章**（birdreport「疑问/无疑问」审核字段）：值得做，但抓取管线没存该字段。Backlog，数据合作后从源头拿。
- **现状与趋势建模、邮件 Alerts、账号态清单、媒体库**：成本/场景不匹配（研究 §13）。

## 4. 功能定义

### 4.0 看什么（真实数据）

**问题：**"我去这个地方，能看到什么鸟？"——三问里最高频的一种。

**形态：两级探索，从城市收敛到鸟点。**

1. 选城市 → 地区概览：地图（圆点大小=鸟种丰富度）+ 鸟点排行（鸟种数/清单数/种每单，可切排序）。回答"哪个点值得去"。
2. 选鸟点 → 该点名录，按遇见率降序。地图保留为定位缩略图，选中点高亮。

**名录每行：** 中文名 + 英文名；遇见率（含该鸟清单数 ÷ 该点总清单数，与 eBird frequency 同口径）+ 频率条，分三层直觉呈现（几乎必见 / 有机会 / 撞大运）；个人标记（目标/学习/已见/笔记）；外链（eBird / 懂鸟 / 鸣声）。

**可信度内建于界面：**
- 名录标明基于多少份清单，N<15 提示「仅供参考」；
- 点「N 份清单」可逐份核对原始报告——每个数字可追溯；
- 鸟点名规范化合并，透明标注「合并 N 处」，可查原始写法。

**目标鸟种**是本页的筛选视角（4e）；**导出鸟单**文件头带地区、时段、来源。

**边界：** 真实无数据的地区+月份组合显示「无记录」空态，不崩溃、不显示 0% 假列表。

#### 🔒 本轮 polish 清单（内部，交付版删除）

基线：两维选择器 + 规范化鸟点已上线，本轮只 polish 不动结构，范围仅限：
- thin 数据 / N<15 措辞对数据专家受众是否够准；
- 空态文案区分「无记录 vs 数据未导入」；
- 报告弹窗可点通、「明细待抓」清晰（对外版按 IS_PUBLIC 隐藏工程注释）；
- 导出鸟单文件头完整；
- 演示前人工过一遍丽江/拉萨鸟点下拉，漏网写法补 `lib/spots.js` 别名表；
- 演示机首屏流畅（视觉感知即可，不量化）。

不做：改数据逻辑、频率算法、选择器结构。polish 中发现的数据层 bug 记 TODO，本轮不修。

### 4a. 鸟种分布图（示例数据）

**问题：**"这种鸟在哪里、哪个季节最常见？"

需要全国尺度坐标数据，超出当前覆盖——各功能中唯一保持 filler/demo 定位的。

**交互：**
- 入口：「去哪儿看」tab（分布图即本 tab 内容），或从名录/柱图的鸟种行跳入。
- 输入：单个鸟种（中文名，模糊搜索）。
- 输出：地图圆点，大小=记录数、颜色=主要季节（春夏秋冬四色）。可缩放平移；点圆点显示地点名、记录数、季节分布。

**数据：** 全部 filler。鸟名地名真实，数字坐标为构造示意值；字段结构与未来真实数据一致（切源不改前端）；界面固定标注「示例数据」（§5）。

**边界：** 预置 3–5 个鸟种的 filler，不临场生成；filler 中不得出现国家级保护动物精确坐标（即使虚构，也避免演示中引出敏感坐标讨论）；坐标落点演示前人工核查；搜不到的鸟种显示「未找到该鸟种数据」，不崩溃。

**不做：** 多鸟种叠加、时间轴动画、迁徙路径连线。

### 4b. 地区探索页（真实数据）

**问题：**"去这个地区观鸟，整体情况怎么样？"

**入口：** 从任一 tab 点选地点进入（实体页，非 tab）。输入 = 地区（现有地点选择器层级）。

**五个区域**（顺序工程自定）：
1. **概览**：鸟种总数、报告总数、覆盖年份（regions/*.json 真实导出）。
2. **热点地图**：圆点大小=报告数；点击显示热点名与报告数。
3. **鸟种列表**：频率最高 20–50 种：中文名、频率%、最佳月份。
4. **季节直方图**：12 个月报告量柱图（报告数，非鸟种频率）。
5. **近期记录流**（4f 内嵌）。

页面明确展示「当前数据覆盖：云南、西藏」。

**边界：** 覆盖外地区显示「当前暂未覆盖该地区，数据覆盖范围：云南、西藏」，不崩溃、不显示全零；静态导出演示期间不动态更新，受众问其他地区就如实说明覆盖范围，不临场造数据。

**不做：** 地区间对比、自定义区域、多年趋势。

### 4c. 多物种柱图（真实数据）

**问题：**"几个目标鸟种，什么时间去能同时覆盖最多？"

「何时去」页已有单物种 12 月柱图，bundle 已支持多物种查询——原地升级交互层，不建新页。

**交互：**
- 现有搜索框旁加「+ 添加对比鸟种」，可搜索添加、可删除；选择器用现有 taxa 真实数据。
- 同时叠加 2–4 个鸟种，每种一色，图例一一对应。
- 突出标注「窗口交集」= 所有选中鸟种频率均达阈值的月份区间（阈值工程自定，建议各鸟当月 >10% 或 >各自峰值 50%，演示合理即可）。

**边界：**
- 鸟种在 bundle 无数据 → 显示「该地区暂无此鸟种数据」，不用 filler 填充，其余鸟种不受影响。
- 添加第 5 种 → 提示「最多同时对比 4 个鸟种」，不允许添加。
- 交集为空 → 显示「所选鸟种无共同最佳时间窗口」，不空白不报错。

**不做：** 旬级叠加、导出叠加图、悬停数据点弹窗（基础版即可）。

### 4d. 频率网格（真实数据，省级）

**问题：**"这个地区哪些鸟哪个月最值得关注？" 对标 eBird Illustrated Checklist / Bar Charts。

**形态：** 行=鸟种、列=12 月、格深=当月频率。province bundle 已有每种×12 月计数与分母，客户端直接算，不新增管线。

**交互：**
- 入口：地区探索页内嵌区块。输入：省份（限覆盖省份）。
- 频率 0 的格子视觉明显区分（空白/灰底），不显示 0%。
- 行可按最高频率月或科属排序，可切换。
- 点格子显示该鸟该月频率% + 样本量 N。

**诚实性：** N 小（参考 N<15）的格子斜纹/半透明标注，不粗暴清零；来源标注第一屏可见；**分母行**——网格底部一行显示各月完整报告数。eBird 把分母藏在 CSV 下载里，我们摆明面——演示受众是数据方，这是诚实性卖点。

**边界：** 覆盖外省份显示「当前暂未覆盖该省份」，不画空网格。

**不做：** 市/县级下钻、跨省对比、导出网格图、格子动画、周级分辨率（Backlog，见 §3 🔒）。

### 4e. 目标鸟种（真实数据 + 本地标记）

**问题：**"该地区有哪些我还没见过、值得去找的鸟？" 对标 eBird Target Species。

**位置：**「看什么」的筛选视角（全部鸟种 / 目标鸟种切换），不是独立页。

**逻辑：** 目标鸟种 = 地区名录（regions/*.json 或 province bundle，真实数据）− useMarks 标「已见」的种，按地区频率降序。标记/取消后列表实时更新。

**边界：** useMarks 为空 → 两视角相同，提示「标记已见鸟种后，此处将只显示未见鸟种」；地区名录为空 → 空态与全部视角一致。

**账号依赖：** 标记只存 localStorage，换设备即丢——账号系统因此是产品必备（§8）。本轮本地标记 + 导出/导入备份过渡，账号上线后一键迁移并入。

**不做（本轮）：** 云端同步（随 §8 交付）、跨地区合并视图、稀有度/难度标注。

### 4f. 近期记录流（真实数据）

**问题：**"这个地区最近有什么新记录？" 对标 eBird Recent Visits。

**位置：** 地区探索页内嵌区块，不是独立页。

**形态：** 最近 20–50 条报告倒序：日期、地点、鸟种数、「明细待抓」标注（复用现有机制）。有明细的可展开或跳转看鸟种列表。区块头部标数据来源与时间范围。

**数据：** 优先用现有导出文件；不满足时可选新增 recent.json 聚合导出（本轮唯一允许的管线改动，可选）。

**边界：** 无近期报告 → 「暂无近期记录」，地区探索页其余区块正常；「明细待抓」不展开、不显示虚假明细。

**不做：** 跨地区合并、社交功能、推送通知、明细补抓。

### 4g. 招牌种 badge（加分项，真实数据）

**问题：**"这个鸟点相对别处强在哪，值不值得专程去？" 对标 eBird Iconic Birds。纯频率榜答不了——麻雀在哪都 90%，需要相对量。

**算法：** `招牌指数 = 该种本点频率 ÷ 该种全省年频率`。点频率来自 points/*.json，省频率 = province bundle 月度计数 ÷ total_reports——两个既有文件，客户端算，不动管线。门槛：倍数 >3 且点样本 N≥5；每点最多标 3 种，防滥。

**呈现：** 鸟点叶子页名录中，命中的种加金色小 badge「全省 N 倍」+ ⓘ 口径说明。

**定位：** 加分项，做不完不阻塞演示；做完是高光时刻（"你们的数据能直接回答'值不值得专程'——纯排行榜给不了"）。不满足门槛的点正常显示、无 badge（优雅缺席）。

**不做：** eBird 原版 10 年窗口/30% 年份门槛（数据只有 2024–25，简化即可）、跨点对比页。

## 5. 数据诚实性（硬约束）

优先级高于一切功能细节，不因工期降级，覆盖全部功能模块。

**为什么：** 演示对象是数据的产生者和维护者。「用你们的数据做出来的」比漂亮的假数据更有说服力；若虚构数字被误认为来自其真实数据库，直接破坏合作基础。

**规则：**

1. 示例数据必须显式标注「示例数据」，且为界面元素（非注释、非 URL 参数）。
2. 标注在页面标题区或数据区头部、第一屏内，视觉上与正文明显区分，不埋页脚小字。
3. 真实与示例数据不得混排在同一图表/列表：分区分别标注，或整体用一类。
4. 示例数据的鸟名地名用真实名称，数字为构造示意值（不声称来自真实统计）。
5. 切换数据源不改前端展示代码：标注由 provider 层 isDemo 驱动，isDemo=false 时自动消失，不靠人工摘除。本轮只需切换路径设计清晰，不必真正跑通。

**真实数据功能**（看什么、地区探索页、多物种柱图、频率网格、目标鸟种、近期记录流）必须清晰展示：
- 数据来源：中国观鸟记录中心（birdreport.cn）；
- 覆盖范围（云南 + 西藏）与年份（`report_years`，当前 2024+2025）；
- 样本量 N，N<15 的月份/格子灰化 + 「仅供参考」；
- 「明细待抓」诚实标注，演示前不得悄悄移除。

## 6. 架构约束

**6.1 静态优先**：维持「静态 JSON 导出 + 纯前端 SPA」，本轮不引入任何在线后端。

**6.2 数据 provider 层**：页面组件只依赖统一数据接口，不直接绑定数据文件/API 端点；源可在示例数据、birdreport 导出、未来 eBird API 间切换；「示例数据」标注由 isDemo 驱动（§5 规则 5）。

**6.3 信息架构：两根轴——三个查询 tab + 一个实体页。**
- 顶部 3 tab（对外版）= 三问（§1）：**看什么**（城市→鸟点→名录，含目标鸟种视角、招牌种 badge）、**何时去**（单物种柱图 + 对比叠加，原地升级）、**去哪儿看**（分布图）。
- **地区探索页 = 实体页，不是 tab**：从任一 tab 点选地点进入，聚合全貌，横跨三问。原「探索」落地页取消。
- 目标鸟种 = 筛选视角；频率网格、近期记录流 = 地区探索页内嵌区块。均非独立页/tab。
- 对外/dev 差异统一走 `lib/mode.js` 的 `IS_PUBLIC`（构建时注入），无运行时开关。
- **URL 深链**：地点写进 `&r=`（城市 id / point_id），「看什么」与地区探索页共用，刷新/分享不丢状态。后续参数族（`&m=` 月份、`&spp=` 鸟种）见 design_spec §3.4，本轮不做。

**6.4 数据管线改动最小化（硬约束）**：仅近期记录流可选新增 recent.json；其余功能不改 export_json.py、不新增导出脚本。演示前不因功能需要突破。

## 8. 账号系统与用户协议（产品必备，排期另定）

**8.1 账号系统**

目标鸟种 = 地区名录 − 用户已见，用户标记是核心输入，只存 localStorage 换设备即丢——账号是必备，不是可选。最小形态：轻量登录（工程选型）+ 标记云端同步 + 本地 useMarks 一键迁移。不在本轮：本轮本地标记 + 导出/导入过渡，账号上线后无感并入。

**8.2 用户协议（要点）**

1. **非商用、不收费。**
2. **数据归用户**：观测记录所有权归个人；平台只用聚合数据，不主张所有权。
3. **CC 4.0 共享**聚合数据（变体待定稿：非商用立场下 CC BY-NC 4.0 更一致，学术无障碍引用则 CC BY 4.0 更开放；发布前确认）。
4. **默认入池、可退出**：可随时 opt out，退出后数据不再进入后续聚合发布。

条款细化与法务审校在发布前完成；界面呈现（注册告知、opt-out 开关）随账号系统交付。

## 9. 未来方向（for future reference，不排期）

**9.1 数据空白格激励（25km 网格）**

记录中心数据有 25km×25km 方格维度，西部大量方格从无记录，记录中心希望鼓励补采。潜在功能：「空白格」探索图层——地图显示哪些方格没有记录，引导用户去补（空间版的集体缺口游戏化）。产品位置未定（分布图图层 / 地区探索页 / 独立任务入口）；依赖记录中心方格级覆盖数据（或坐标自算）；价值在与数据方增长诉求直接对齐，是天然共建话题。

**9.2 鸟点主数据与 Hotspot 档案页（志愿者整理·提案，需与朱雀会确认后启动）**

问题：记录中心点位大量用户自建（「随手记/定点记」使然），名字不统一、同地多点（丽江老君山一处多个重复点）；前端别名表（`lib/spots.js`）是权宜之计。计划：志愿者按城市整理权威鸟点表（正式名、别名、坐标、区县），按记录量优先，覆盖到每城约 95% 记录，长尾走自动规范化兜底；成果升级为数据层点位 id 映射表。随之解锁 **Hotspot 档案页**——组件与地区探索页全复用，主数据就绪即低成本上线（对标 eBird 热点体系及志愿者维护的 About 页）。价值：对数据方即点位数据治理，又一共建点。

**9.3 其它 Backlog**

周级（48 格）频率柱图 · 置信度徽章（对接审核字段）· 完整移动端 IA（design_spec §2）。
