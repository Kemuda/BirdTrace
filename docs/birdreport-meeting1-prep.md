# 第一次拜访 birdreport.cn / 昆明朱雀会 —— 会前提纲

> 定位:**第一次见面 = 摸底 + 建立关系**
> 循序渐进:这次只求「我懂了他们的家底 + 他们觉得我靠谱」。
> 最后更新:2026-07-02

---

## 0. 目标

- **信息**:摸清他们的后端技术家底、数据现状；团队dynamic， roadmap；什么对他们重要
- **关系**:让理事长觉得「这人认同我们的使命」;让数据负责人觉得「这人技术上靠谱、不添乱」。


---

## 1. 三条贯穿全程的心法

1. **好奇模式,不是索取模式。** 多问「你们怎么做的 / 为什么这么设计」,少说「我想要」。
2. **反爬这件事,诚实但谦逊地翻篇。** 建议开场白式表述:
   \> 「我用你们的公开数据搭了个前端原型,想做个更好用的非商业的探索界面(对标 eBird Explorer);做着做着撞上了你们的反爬——这其实正是我想来正经聊一聊的原因。」
   一句话把「我爬过你们」从把柄变成来意,还顺带承认他们防护有效。数据负责人很可能就是建反爬的人,他会受用。
3. **把他们的痛点当宝。** 他们想用数据做什么、卡在哪 —— 那就是你日后能帮上忙、换到合作的地方。

---

## 2. 对理事长- 对齐

不谈技术细节。目标是让他把你归类为「自己人 / 使命放大器」。

- 你们做这个平台最初的初心和现在最想推动的是什么?
- 数据现在主要服务哪些群体(科研 / 保护 / 公众观鸟)?哪块最想做大?
- 你们怎么看数据的社会价值 vs 保护风险(比如敏感物种坐标)之间的平衡?
- 怎么看待现在市面上这些工具之间的合作或者竞争关系？
- 团队、优势和劣势
	- 
- funding 情况和体制的支持
	- 


> 埋一颗种子即可:你是公益、互补、不抢生意。别展开谈合作。

## 3. 对数据负责人(北大 · 管数据产品)—— 本次重点,技术深聊

peer-to-peer 技术对话。你越显得懂数据治理,他后面越愿意给你开方便之门。按主题分组,**挑着问,不用全打完**(这是第一次,留话题给下次)。

### 3.1 数据模型与 schema
- 核心实体大概怎么组织的?我理解是 `用户 → 报告/清单 → 观测记录 → 物种`,加地点和审核两条支线 —— 对吗?
- 分类系统怎么做版本管理的?(CH3/CH4)遇到**拆种/合种(split/lump)**历史记录怎么迁移?
- 地点是怎么建模的?有没有一套**规范化的点位/热点系统**,还是用户自由填文本?
- 经纬度存在哪一层?精度多少?对**敏感物种**有没有坐标模糊化/分级?
- 「疑问 / 无疑问」审核工作流具体怎么跑?有哪些状态?谁来审?异常怎么自动标注的?

### 3.2 存储与规模
- 后端大概用什么数据库?现在的数据量量级(报告数 / 观测记录数 / 已记录物种数)?
- 增长速度大概每月多少条?
- 有没有把**分析型查询**和**线上事务**分开(读副本 / 数仓)?

### 3.3 接口与数据流
- App / 小程序 / Web 站是怎么跟后端对接的?(听他怎么描述现有 API)
- 有没有对外的数据导出通道?研究者现在想批量拿数据一般走什么流程?
- **你们已经在 GBIF 或别的平台发布数据了吗?** 有没有这个计划?
- 反爬做得挺重的 —— 主要是防什么?(理解他们的顾虑边界:防商业倒卖?防服务器压力?)

### 3.4 数据标准与互通
- 有没有做过 **Darwin Core / GBIF** 标准化映射?
- 物种编码跟 **eBird / 其他系统**有没有对照表?(你手里有 eBird crosswalk,可作为共同话题)
- 照片/媒体怎么存和管理的?(你已知是阿里云 OSS,可印证)

### 3.5 团队与 roadmap(听痛点!)
- 数据产品这块现在几个人在做?怎么分工?
- **你们自己最想用这些数据做成什么、现在卡在哪?**(← 最重要的一问,答案就是你日后的切入点)
- 未来 12 个月数据产品方向大概是什么?

### 3.6 🔵推断 / ⚪未知 待求证清单(逐条对照)

下面每一条都是架构分析文档里**还没坐实**的点。目标:这次尽量把 🔵/⚪ 变成 🟢 实测。不用一次问完,但这是「问到哪算哪」的核对表。
